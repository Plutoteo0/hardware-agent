# Прогресс: 2026-10-05

## Где мы сейчас
- ПК с RTX 4060 (8 ГБ VRAM), Ollama, модель по умолчанию `qwen3:8b`.
- **Работает end-to-end с железом и голосом:** держишь кнопку и говоришь → звук по Wi-Fi на сервер → Whisper (CPU) → `Session` → `OllamaModel` → тулы (файлы + интернет) → карточка подтверждения на экране, YES/NO энкодером → ответ на экране и голосом (Piper, CPU) из динамика платы.
- Терминальный клиент тоже работает (с самого ПК, без токена).

## Как запустить
1. Сервер (из корня, `.venv`):
   `.venv\Scripts\python.exe -m uvicorn main:app --app-dir server --port 8001 --host 0.0.0.0`
   `--host 0.0.0.0` нужен, чтобы плата видела сервер. Токен сервер берёт из `.env`.
2. Плата сама подключается после включения. Вверху справа `W` и `S` заглавные = Wi-Fi и сервер на связи.
3. Терминальный клиент (PowerShell): `$env:AGENT_URL = "ws://127.0.0.1:8001/ws"`, потом `.venv\Scripts\python.exe client\terminal.py`.
4. Прошивка (из `firmware/`): `C:\Users\plutoteo\.pio-venv\Scripts\pio.exe run -t upload`. PlatformIO стоит в своём venv вне проекта.
5. Тесты: `.venv\Scripts\python.exe -m pytest`.

## Файлы
Сервер:
- `server/protocol.py` — сообщения. Клиент → сервер: `Task`, `Decision`, `Cancel`. Сервер → клиент: `Status`, `ConfirmRequest`, `Result`, `Error`.
- `server/tools.py` — тулы и таблица рисков `RISK`, `safe_path`. Файлы в UTF-8.
- `server/web.py` — `web_search` (HTML-версия DuckDuckGo, без ключа) и `fetch_url` (только http/https, внутренние адреса и редиректы туда закрыты, текст до 4000 символов).
- `server/models.py` — `Model`, `MockModel`, `OllamaModel` (`format="json"`, `think=False`, `num_ctx=8192`), `parse_step`, `SYSTEM_PROMPT`.
- `server/session.py` — агентный цикл, подтверждения, таймаут = отказ, отмена. Тулы идут в `asyncio.to_thread`, чтобы сеть не блокировала приём `Decision`/`Cancel`.
- `server/stt.py` — распознавание речи: faster-whisper `small`, CPU, int8, все ядра. ~3 с на фразу.
- `server/tts.py` — озвучка: Piper, голоса в `voices/` (не в git), ~14× быстрее реального времени. `speech_text` убирает ссылки и разметку, режет до ~600 символов.
- `server/main.py` — FastAPI, `/health`, `/ws`. Подключения из сети только с `Authorization: Bearer <AGENT_TOKEN>`; с `127.0.0.1` без токена. Мини-загрузчик `.env`.
- `server/tests/` — `test_tools.py`, `test_session.py`, `test_web.py`, `test_auth.py`.

Клиенты:
- `client/terminal.py` — терминальный клиент.
- `firmware/` — прошивка T-Embed (PlatformIO + Arduino):
  - `platformio.ini` — плата, библиотеки, настройки экрана флагами.
  - `boards/t_embed_cc1101.json` — описание платы из репозитория LilyGO.
  - `include/pins.h` — пины (из `examples/utilities.h` LilyGO).
  - `include/button.h` — клик / удержание с антидребезгом.
  - `include/textview.h` — текст с кириллицей (U8g2, шрифт 9×15), перенос по словам с учётом UTF-8, прокрутка.
  - `include/secrets.h` — Wi-Fi, адрес ПК, токен. **Не в git.** Шаблон: `secrets.example.h`.
  - `include/mic.h` — PDM-микрофон, I2S0, 16 кГц.
  - `include/speaker.h` — динамик, I2S1, кольцевой буфер 512 КБ в PSRAM + задача FreeRTOS на ядре 1, программная громкость (0.6).
  - `src/main.cpp` — режимы Menu / Working / Confirm / Recording / Answer, Wi-Fi, WebSocket, голос.

## Протокол (WebSocket /ws)
- Клиент → сервер: `hello{speech}`, `task{text}`, `decision{id, approve}`, `cancel`, `audio_start`, двоичные кадры (PCM s16le 16 кГц моно), `audio_end`.
- Сервер → клиент: `status`, `confirm_request{id, tool, args, timeout_s}`, `transcript{text}`, `result`, `error`, `speech_start{sample_rate}`, двоичные кадры озвучки, `speech_end`.
- Озвучку получают только клиенты, приславшие `hello` со `speech: true` (терминальный клиент — нет).
- Озвучка идёт кусками по 0.2 с, не дальше 2 с вперёд реального времени.

## Железо и сеть
- Плата на COM3, в Wi-Fi получает `192.168.1.125`. ПК: `192.168.1.13` (записан в `secrets.h`; лучше закрепить в роутере).
- **Резервная копия заводской прошивки:** `C:\Users\plutoteo\Desktop\tembed-backup\tembed_factory_backup.bin` (полные 16 МБ). Вернуть: `esptool --port COM3 write-flash 0 tembed_factory_backup.bin`.
- `num_ctx`: 8192 влезает в GPU целиком (6.2 ГБ). 12288 → 13% на CPU, 16384 → 20%, 24576 → 31%. Оставили 8192. Порог сводки ~70% ≈ 5700 токенов (ещё не реализован).

## Что проверено
- `pytest`: 32 прошли, 1 пропущен (симлинк на Windows).
- С платы руками: список файлов, чтение, запись с YES и NO, поиск в интернете, отмена, голосовые вопросы, озвучка ответов.
- Голос: громкость микрофона хорошая (peak 0.17–0.35, без перегруза), фразы распознаются слово в слово; ошибся на «Вроцлаве» («Вротславе»).
- Whisper `small` на 12 потоках: 3.2 с на фразу 3.3 с (на 4 потоках было 4.7 с). Piper: 10 с речи за 0.8 с.
- Через WebSocket скриптами: `web_search` + `fetch_url` дают точный факт (версия httpx 0.28.1), `127.0.0.1` блокируется, токен: без него / в адресе — отказ, в заголовке — пускает.
- Исправлено по пути: модель обрезала расширения файлов; выдумывала причину отказа; путала ERROR с отказом; возвращала `{"error": ...}`; отвечала по сниппету без открытия страницы; cp1251 на Windows; гонка за stdin в клиенте; токен попадал в лог uvicorn (перенесён в заголовок).

## Что не проверено
- Таймаут подтверждения (30 с) на плате и в терминальном клиенте.
- Поведение платы при перезапуске сервера посреди задачи (по коду: возврат в меню, переподключение каждые 3 с).
- Модель отвечает из своих знаний, если «уверена» (так решили), и может ошибаться. Проверок стабильности мало (5–8 задач).

## Что мы разобрали (для себя)
- `Decision` идёт клиент → сервер, связь с запросом через `id`. Чужой `id` сервер игнорирует.
- В `main.py` задача запускается через `create_task`, иначе цикл не принял бы `Decision`.
- `OllamaModel`: результат тула уходит модели как сообщение пользователя с подписью; шаг модели (`assistant`) идёт в историю перед результатом.
- `parse_step`: `try` даёт понятную ошибку; `isinstance(dict)` нужен, потому что валидный JSON бывает числом или списком; `final` проверяется первым.
- `terminal.py`: состояние подтверждения в словаре `state` — изменяемый объект, обе корутины видят одно значение.
