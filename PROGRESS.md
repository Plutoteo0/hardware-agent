# Прогресс: 2026-10-04

## Контекст сессии
- Работали на маке (arm64), без RTX 4060 и без T-Embed. Поэтому вместо реальной модели — MockModel, вместо ESP32 — терминальный клиент.
- Код писал Claude с объяснениями (разрешено только для этой сессии).

## Что сделано
- Обсудили `BRAINSTORM.md`, главные риски:
  - tool calling на моделях 7–8B может быть нестабильным
  - `num_ctx` под 8 ГБ VRAM
  - обрыв связи при подтверждении
- Решили: пока нет железа, строим цепочку «сервер → mock-модель → терминальный клиент».
- Окружение: `.venv` с fastapi, uvicorn, websockets, pytest.
- Написан каркас (файлы ниже).

## Файлы
- `server/protocol.py` — типы сообщений (pydantic). Клиент → сервер: `Task`, `Decision`, `Cancel`. Сервер → клиент: `Status`, `ConfirmRequest`, `Result`, `Error`.
- `server/tools.py` — тулы `list_tree`, `read_file`, `write_file`, таблица уровней риска `RISK`, `safe_path` (защита от `../` и симлинков через `resolve()`).
- `server/models.py` — интерфейс модели и `MockModel` (команды `ls`, `read <path>`, `write <path> <text>`).
- `server/session.py` — агентный цикл, подтверждения через `id` + future, таймаут = отказ, лимит шагов, отмена.
- `server/main.py` — FastAPI, `/health`, WebSocket `/ws`.
- `client/terminal.py` — терминальный клиент (ввод текста, подтверждение `y/n`, `/cancel`).

## Проверка 2026-10-05
Сервер запускается, `/health` отвечает. Скриптом (WebSocket) прогнали: write с подтверждением и с отказом, read, ls, выход из песочницы (`../`), неизвестная команда, невалидный JSON, чужой `id` решения — всё ведёт себя как задумано.
- Порт 8000 на маке занят чужим процессом, сервер запускаем на 8001: `.venv/bin/uvicorn main:app --app-dir server --port 8001`, клиент: `AGENT_URL=ws://127.0.0.1:8001/ws .venv/bin/python client/terminal.py`.
- Не проверено: таймаут подтверждения (30 с), `/cancel`, интерактивный терминальный клиент руками, симлинк наружу. Автотестов (pytest) ещё нет.

## Что мы разобрали (для себя)
- `Decision` идёт клиент → сервер, это ответ на `confirm_request`, связь через `id`.
- Пользователь вводит только текст, JSON собирает клиент (`terminal.py`).
- `validate_json` читает поле `type`, выбирает класс и создаёт объект. `isinstance` потом проверяет, какой это класс.
- `Annotated[..., discriminator="type"]` только описывает схему, объект создаёт `validate_json`.
- В цикле `main.py` задание запускается через `create_task`, иначе цикл завис бы и не принял `Decision`.
