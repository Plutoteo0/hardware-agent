# Portable agent (T-Embed + локальная модель)

## Идея
Портативный агент: мозг на сервере (FastAPI + Ollama на RTX 4060), LilyGO T-Embed (ESP32-S3) как периферия: экран, энкодер, позже микрофон и динамик.

## Принятые решения
- Сначала терминальный клиент, чтобы проверить поток данных end-to-end. ESP32 потом подключается как второй клиент с тем же протоколом.
- Сначала экран + подтверждения, голос потом.
- Голос только для заданий и озвучки результата ("сделал X, получилось Y"). Разрешения и выбор тулов только через энкодер, голосом не подтверждаем.
- Уровни риска тулов: авто (веб-поиск и т.п.), спросить (правка кода, команды), запрещено (свой список).
- Агент видит одну папку (песочница) + Docker-контейнер для запуска тестов.
- Новая сессия модели + новый контейнер, когда контекст заполняется. Перед этим агент выгружает сводку в .md.
- Из сводки: главная идея, последнее задание. Код и изменения берём из файлов, а не из пересказа модели.
- Сервер отдаёт список изменённых файлов, модель сама запрашивает нужные (git diff через отдельный read-only тул).
- Для первой версии: read-only тулы поиска (list_tree, grep, read_file) + checkpoint-коммиты. Карту проекта и индекс символов добавим позже, если модель будет терять контекст.

## Заметки по реализации (наши рассуждения, не требования)
- Контейнер: монтировать только рабочую папку, без docker.sock, без root, cap-drop, лимиты CPU/RAM, таймаут, сеть выключена по умолчанию.
- Проверка путей на сервере (../, симлинки).
- Окно контекста считать по prompt_eval_count/eval_count Ollama, проверить num_ctx. Сохранять сводку примерно на 70% заполнения.
- В сводку добавить поле "что сделано / что осталось".
- Файл передачи пишет сервер (не тул агента), содержимое подавать новой сессии как данные, не как инструкции. Висящие подтверждения после рестарта запрашивать заново.
- Карточка подтверждения показывает реальный вызов тула и аргументы, а не пересказ модели.

## Открытые вопросы
- Формат протокола: типы сообщений (запрос, ответ, запрос подтверждения, решение, статус), что делать при обрыве связи во время подтверждения.
- Как агент узнаёт о неизменённых, но нужных файлах (дерево, grep?).
- Один постоянный контейнер на сессию или новый на каждую команду.
- Что делает долгое нажатие энкодера.
- Канал для "портативности": туннель до домашнего сервера или бесплатные облачные модели.
- Прошивка: ESP-IDF или Arduino/PlatformIO.
